Commercial Architecture Overview

Security & Privacy Architecture

Authoritative Principles • Technical Safeguards

CHARLIE is engineered with a strict local-first security model. We separate client execution from commercial entitlement authority to protect customer privacy and data integrity.

Server-Side Licensing Truth

The desktop client is never the authority on subscription tiers or payment status. Entitlements are signed with server-held 2048-bit RSA keys and verified locally using public keys.

Zero Financial Data Storage

All transactions run through PCI-DSS Level 1 compliant gateway endpoints. CHARLIE servers never handle or store raw card numbers, CVVs, or payment passwords.

Privacy-Minimized Device Identity

Device binding uses irreversible SHA-256 salted hashes of machine hardware properties. We never harvest MAC addresses, IP histories, or private system metadata.

Cryptographic Auto-Updates

Every official release is packaged into a standalone installer with published SHA-256 checksums. Unsigned patches or tampered files fail validation automatically.

Automation & Computer Control Safety

CHARLIE desktop automation operates under a tiered capability policy:

  • Human-in-the-Loop Confirmation: Critical file deletions, bulk email actions, and system modifications require explicit user approval.
  • Local Processing Boundaries: Voice recognition and spreadsheet parsing run locally on CPU/GPU without transmitting documents to third-party endpoints.
  • Isolated Agent Sessions: Subagents run in isolated execution frames with audited tool privileges.

Responsible Disclosure

Security researchers can report vulnerability disclosures directly to our security engineering team through the Support Center.
